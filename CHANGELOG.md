# Changelog

All notable changes to this project are documented here. The format follows
[Keep a Changelog](https://keepachangelog.com/en/1.1.0/) and the project uses
[Semantic Versioning](https://semver.org/).

## [1.0.1] - 2026-11-25 — Reliable tests

A patch release: no change to the application's behaviour. The tests now give the same verdict on a busy machine
as on a quiet one, and the flash sale runs in CI.

### Added
- **Load test in CI** ([`.github/workflows/load-test.yml`](.github/workflows/load-test.yml), [#141](../../pull/141)): a
  200-staff flash sale through nginx and both backends on every pull request into `main`, nightly on `develop`, and on
  demand. One command for local runs and CI: [`load-tests/run-flash-sale.sh`](load-tests/run-flash-sale.sh).
- **Database check after every load test** ([`load-tests/assert-db.sql`](load-tests/assert-db.sql)): no overbooking,
  slot counters equal confirmed rows, no duplicate claim, and as many claims in the database as `201` answers.

### Changed
- **The flash sale gates on correctness**, not on a machine-dependent latency ([#141](../../pull/141)): a `503` with
  `Retry-After` (the SG-81 fail-fast answer) is retried like a person would, and every staff member must end with
  `201` or `409 SHIFT_FULL`. Latency is still reported; `P95_MS` re-enables a latency gate on a quiet server.
  5 consecutive 1000-staff runs passed ([`load-tests/results/03-reliability.md`](load-tests/results/03-reliability.md)).
- Backend image health check: start period 60 s → 120 s, so a slow start on a busy host is not reported unhealthy
  (a healthy answer still counts at once).

### Fixed
- `MultiInstanceClaimTests` failed now and then on slow machines (`SERVICE_BUSY`): it predated the SG-81 pool and
  row-lock timeouts ([#140](../../pull/140)). The backend suite then passed 3 times in a row.

## [1.0.0] - 2026-11-24 — Sprint 9: hardening, operations and documentation

First stable release. The complete feature set of the SRS is in place, tested at every level and deploy-ready.

### Added
- **Security review** against OWASP Top 10:2025, with evidence per category ([`docs/security/owasp-top10-review.md`](docs/security/owasp-top10-review.md), [#46](../../issues/46), [#134](../../pull/134)):
  - Content-Security-Policy (`script-src 'self'`, `frame-ancestors 'none'`) and security headers on every response;
  - a per-address rate limit on Keycloak login form posts (`429`);
  - a password policy in the production realm;
  - control characters refused in shift and template names.
  - The E2E journey now fails on any CSP violation.
- **Operations runbook** ([#44](../../issues/44), [#135](../../pull/135)): incident checklist, a playbook per alert, and rotation of every secret (each procedure tested on the local production stack).
- **README** in English and Vietnamese, with a demo GIF, screenshots generated by Playwright, and a three-command quick start using `infra/docker/.env.local.example` ([#45](../../issues/45), [#136](../../pull/136)).
- `e2e` is a required check on `main`.

### Changed
- Dependencies: Spring Boot 4.2.0, Spring Modulith 2.2.0, springdoc 3.2.1, Prometheus 3.16, Grafana 13.3.1 (start-up re-checked: 6 s, ~1.5 % CPU), nginx 1.31 for the edge and the web image.
- Dependabot keeps majors of the Java runtime, the Node build image and certbot as planned upgrades, with the reasons in `dependabot.yml` ([#137](../../pull/137)).
- Architecture document updated to the SG-81 claim flow (lock per user, versioned conditional update).

### Fixed
- **Grafana never finished starting** within its memory limit: Grafana 13 started 13 data-source plugin processes at ~800 % CPU. Only the Prometheus plugin runs now, with 256 MiB: ready in 6 s at ~1 % CPU ([#135](../../pull/135)).
- `index.html` was served without `Permissions-Policy` (nginx `add_header` inheritance) ([#134](../../pull/134)).
- A flaky concurrency test that depended on the 1 s pool timeout ([#133](../../pull/133)).

## [0.8.0] - 2026-11-24 — Sprint 8: Load test, tuning and end-to-end tests

### Added
- k6 flash-sale load test: 1000 staff claim 50 slots at the same instant through nginx and both backends. A generated throwaway realm provides the accounts; `verify-db.sql` checks the database against the HTTP answers. Baseline report included ([#41](../../issues/41), [#126](../../pull/126)).
- Playwright end-to-end journey on the real production stack: Keycloak login, a manager creates a shift, staff claims and cancels it, and the manager's list follows live. It runs in CI on pull requests into `main`, nightly on `develop`, on demand, and on pull requests labelled `e2e`. Failed runs keep a trace, screenshots, video and container logs ([#43](../../issues/43), [#130](../../pull/130)).
- Error codes `SHIFT_CHANGED` (409) and `SERVICE_BUSY` (503 with `Retry-After`), with Vietnamese and English messages.

### Changed
- **Claims lock the user, not the shift** ([ADR-0004 revision](docs/adr/0004-redis-distributed-lock.md), [#42](../../issues/42), [#127](../../pull/127)):
  - PostgreSQL's row lock orders claims on a shift.
  - The claim transaction is short and bounded: `SET LOCAL lock_timeout` 1 s and `statement_timeout` 2 s.
  - A per-instance sold-out memo answers late requests without a transaction.
  - Connection budget: 25 per backend, Keycloak 20, Hikari timeout 1 s.
  - Flash sale on the same laptop: 503 errors 138 → 0, server-side claim max 6.4 s → 1.26 s, average pool wait 233 ms → about 1 ms. Still exactly 50 claims and zero overbooking.
- SRS: NFR-02 clarified. 300 ms at 500 req/s is the steady-load target, verified on the server; the flash-sale burst has its own target.

### Fixed
- **Deployment on Linux:** shell scripts were committed without the executable bit, which Windows checkouts cannot store. On a Linux server nginx skipped its site selection script and served its default page, and `./deploy.sh` would have been refused. All scripts are now `100755`, and infrastructure CI checks it. Found by the first E2E run on GitHub's Linux runner.
- A manager changing a shift's times while it was being claimed produced a registration with the old times. The claim now checks the shift version and copies the times from the updated row.
- Database connection timeouts and deadlock victims answered 500. They now answer 503 with `Retry-After`.
- Request values are stripped of line breaks before logging (log injection, found by CodeQL).
- The open-shifts page could show 2 booked slots after 1 claim when the live update arrived before the HTTP response (found by the new E2E test).

## [0.5.0] - 2026-11-22 — Sprint 5: Real-time, notifications and audit

### Added
- Live slot updates: STOMP over WebSocket, token checked on CONNECT, read-only channel; Redis pub/sub fans updates out across backend instances; newest update per shift wins (database clock); live indicator and "new shifts" notice in the web app ([#27](../../issues/27), [#100](../../pull/100)).

- Opening reminders 30 minutes before registration opens, opt-in from the profile page, one digest per person, sent exactly once across instances (ShedLock + database marker + outbox) ([#29](../../issues/29), [#99](../../pull/99)).
- Append-only audit log of every business change, written in the same transaction, with `GET /api/v1/audit-log` filters ([#30](../../issues/30), [#96](../../pull/96)).
- Scheduled jobs with ShedLock; resubmission of failed event publications.

### Changed
- Dependabot: TypeScript moves only with Angular; npm dependency updates ([#92](../../pull/92)–[#94](../../pull/94), [#97](../../pull/97)).

### Fixed

## [0.3.0] - 2026-11-22 — Sprint 3: Claiming core and concurrency

### Added
- Distributed lock: `RedisLockProvider` (Redisson) behind `ShiftLockProvider`, ordered keys (user → shift), 3 s wait budget, explicit 10 s lease, fail closed when Redis is down; lock-wait timer metric ([#18](../../issues/18), [#73](../../pull/73)).
- Claim a shift slot with all business rules (BR-01..BR-05): registration window, weekly hour limit split per ISO week, no overlap, atomic slot reservation; flash-sale fast path rejects full shifts before locking ([#19](../../issues/19), [#74](../../pull/74)).
- Cancel a registration before the deadline (BR-06), returning the slot immediately ([#20](../../issues/20), [#75](../../pull/75)).
- My shifts with weekly hours ([#21](../../issues/21), [#76](../../pull/76)).
- Concurrency suite: two backend instances sharing PostgreSQL and Redis, 100 staff vs 5 slots → exactly 5 claims; each defence layer tested alone (ADR-0005) ([#22](../../issues/22), [#77](../../pull/77)).
- Error codes `CLAIM_BUSY` and `LOCK_UNAVAILABLE` (503 with `Retry-After`).

### Changed
- Weekly hour limit (40 h) and cancel deadline (24 h) are deployment settings.
- Dependencies: Redis 8.10.3 image, JaCoCo 0.8.16, Maven 3.10.1, `actions/upload-artifact` v7 ([#66](../../pull/66), [#68](../../pull/68)–[#70](../../pull/70)); Dependabot ignores PostgreSQL major upgrades ([#72](../../pull/72)).

### Fixed
- Parallel first requests of a new user could fail on `uq_users_email` during profile provisioning (one retry).
- Profile provisioning inside a read-only transaction failed; the upsert now runs in its own transaction.

## [0.2.0] - 2026-11-16 — Sprints 1–2: Backend foundation and shift management

### Added

- Edit shifts with `If-Match` optimistic locking; BR-08/BR-09 enforced atomically in SQL ([#13](../../issues/13), [#60](../../pull/60)).
- Cancel shifts together with their registrations in one transaction (BR-07); event with affected staff for notifications ([#14](../../issues/14), [#61](../../pull/61)).
- Recurring shift templates with all-or-nothing, idempotent generation in the organisation time zone, including overnight shifts ([#15](../../issues/15), [#62](../../pull/62)).

- SQLite replaced by PostgreSQL in every environment (ADR-0002).
- Local PostgreSQL published on port 5433 to avoid clashing with a native installation ([#64](../../pull/64)).
- CI actions updated: `actions/checkout` v7, `actions/setup-java` v5 ([#50](../../pull/50), [#52](../../pull/52)).

### Fixed
- A duplicate claim of the same shift was reported as `SHIFT_OVERLAP` instead of `ALREADY_REGISTERED`; the overlap exclusion now only compares different shifts (migration V2).
